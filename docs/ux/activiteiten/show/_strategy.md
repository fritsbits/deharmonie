# UX Strategy — Activity Detail Page
_Status: Draft_

## Why this page exists

The detail page is where interest converts to registration — or where a curious visitor confirms "yes, this is for me." It must answer three questions fast:

1. **What is it?** (and is it for me?)
2. **When and where?**
3. **How do I sign up?**

## User arrivals

Inherited from [`../../../_strategy.md`](../../../_strategy.md) and [`../_strategy.md`](../_strategy.md). No new user types on the detail page — same four:

| User | What they need on this page |
|------|----------------------------|
| **Curious outsider** | Confirmation this is friendly, accessible, low-commitment |
| **Family browser** | Date, time, price — enough to share with their parent |
| **Regular visitor** | Date and time fast. Nothing else. |
| **New regular** | Reassurance through description, easy registration path |

## Core insight

> The page must feel like an open door, not a form.
> The registration form is available — but the page should not lead with it. Lead with warmth and information, then invite.

## Key decisions

- **No activity photo** — typography and logistics carry the page
- **Reeks vs. one-time:** eyebrow label changes ("Conversatietafel" vs "Activiteit"), layout stays identical
- **Registration success:** inline — form collapses into a clear confirmation message
- **Capacity/availability logic:** out of scope — not shown to users
