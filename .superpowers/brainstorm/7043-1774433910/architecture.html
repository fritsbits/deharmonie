How should "tweaking" a component work?

This determines how the style guide connects to the rest of the site. Pick the approach that fits how you want to maintain it.

A

Display-only page (simplest start)

A single Blade view at /stijlgids that shows all components with their names and labels. You tweak a component here to find the right style, then manually copy those styles to the actual pages. No code is shared — just a visual reference.

Pros

  • Zero impact on existing pages
  • Fast to build
  • Easy to understand

Cons

  • Changes don't propagate — you copy/paste to other pages
  • Can drift out of sync with reality
B

Blade components (true single source of truth)

Extract each pattern into a Blade component: <x-btn-primary>, <x-section-heading>, <x-eyebrow>, etc. The style guide page just renders all components. Actual pages use the same components. Edit the component file — every page updates.

Pros

  • Real single source of truth — edit once, updates everywhere
  • Style guide always reflects live styles
  • Gradually refactor existing pages to use components

Cons

  • More work to set up
  • Need to refactor existing pages to benefit
C

Hybrid — display page now, components later

Build the style guide as a display page first. But write it using a component structure internally — so we're already building toward Blade components. The style guide works immediately, and migrating existing pages to use components can happen gradually over time.

Pros

  • Useful immediately
  • Natural migration path
  • Low risk — no impact on existing pages until you're ready

Cons

  • Slightly more up-front thinking than option A
