How should the style guide page be organized?

Two different mental models — both show the same components, but grouped differently.

Option A — By layer (tokens → atoms → molecules)
1. Design Tokens
Colors • Typography scales • Spacing
2. Typography
H1 • H2 • H3 • Eyebrow/label • Lead text • Body • Small
3. Buttons & Links
Primary • Secondary • Dark • Text link • Back link
4. Form elements
Label • Input • Textarea • Submit • Error state
5. Badges & Status
Gratis • Geannuleerd • Volzet • Success
6. Cards & Panels
Sidebar card • Service card • Registration panel
7. Sections
Hero • Agenda list item • Two-col photo section • Opening hours
Option B — By page (top to bottom of the site)
1. Global: Colors & Fonts
All tokens displayed
2. Navigation
Full nav bar preview
3. Hero section
Full hero preview with all sub-elements
4. Agenda section
Activity list item variants
5. Activity detail
Sidebar card • Badges • Registration form
6. Static pages
Services card • Services list
7. Footer
Full footer preview
A

By layer — tokens first, then components

Standard design system structure. Easier to find a specific button or badge type regardless of which page it appears on. Better for applying components to new pages.

B

By page — mirrors how the site is built

More intuitive if you're thinking "I want to change how the hero looks." Each section is a mini-preview of a real part of the site. Better for auditing and refining existing pages.

C

Mixed — tokens + components, then full section previews

Tokens and small components (buttons, typography, badges) at the top. Then full section previews (hero, agenda, sidebar) below. Best of both — reusable pieces and full-context previews.
