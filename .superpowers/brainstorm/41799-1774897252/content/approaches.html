3 approaches for the PDF week menu

How should the "download PDF" link work?

A

Dedicated print-view route

A clean HTML page at /restaurant-menu/print?week=0 — no nav, no footer, styled for A4. User opens it in a new tab and uses browser Print → Save as PDF. Works perfectly on mobile too.

Pros

  • Zero new dependencies
  • Full control over layout
  • Works in all browsers
  • Can preview before printing

Cons

  • User must use browser's print dialog (not a one-click download)
B

Server-side PDF (DomPDF)

Route /restaurant-menu/pdf?week=0 returns a .pdf file directly. One click, file downloads. Uses barryvdh/laravel-dompdf.

Pros

  • True one-click download
  • PDF file in hand immediately
  • Consistent output regardless of browser

Cons

  • Adds a Composer dependency
  • DomPDF has limited CSS support (no Flexbox, no custom fonts from CDN)
  • Needs extra work to match the design
C

Print CSS on the existing page

Add @media print styles to the current weekmenu page. A "Print" button triggers window.print(). No new route at all.

Pros

  • No new route, no new file
  • Zero dependencies

Cons

  • Hardest to control — nav, sidebar, footer all print unless carefully hidden
  • Can't link directly to the print view
  • Fragile across browser/OS print dialogs

⭐ Recommended: A — simplest, most reliable, no dependencies. Seniors can preview the page and then print or save. Staff can bookmark the print URL for each week.
